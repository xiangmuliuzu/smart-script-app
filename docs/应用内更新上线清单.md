## 2. 发布 APK

在本机（Windows bash / Git Bash）执行：

```bash
cd D:/build/smart-script-app
bash scripts/publish_apk.sh 1.0.1 2
```

- 第 1 个参数是版本名，第 2 个是 build 号（`versionCode`），**必须比上一版大**。
- 脚本会：打 release 包 → 用 apksigner 打印证书 SHA-256（与 `android/SIGNING.md` 的指纹核对）→ 复制到
  `smart-script-backend/uploadPath/app/` → 只保留最近 3 个包 → 打印参数。
- `app.version.android.url` 填绝对地址或 `/profile/app/<文件>` 都行，App 会补全为同源地址。
- 如果打包机不是服务器：把 `uploadPath/app/` 下这个 apk 上传到服务器对应目录（容器部署时对应挂载的 `RUOYI_PROFILE` 目录）。
  当前线上服务器是容器 `smart-script-unified`，宿主目录为 `/home/ma_jiajia/uploadPath/app/`，属主必须与后端进程一致（`ma_jiajia`）。
- **MinIO 必须同步**（服务器 `MINIO_ENABLED=true`）：只放本地目录时，`/profile/app/*.apk` 可能因回源 MinIO 而 404。
  后端使用的 `MINIO_ACCESS_KEY` 只有读权限，上传要用容器 root 凭据，且 `mc alias` 与 `mc cp` 必须放在同一个容器里执行，
  否则别名丢失、文件会静默写到容器本地路径。

> ⚠️ **两个签名陷阱**
> 1. 服务器上如果还留着 2026-11-17 之前用 **debug 签名** 打出来的旧 APK，用户装旧包就只能卸载重装才能换新包。给测试同事的包统一改用新 keystore 打。
> 2. 如果换了打包机，先把 `release.keystore` + `key.properties` 拷过去（已在 .gitignore，不会跟着代码走），
>    或用 `SMARTSCRIPT_KEY_PROPERTIES=<外部 key.properties 路径>` 指向已有文件，详见 `android/SIGNING.md`。
> 3. 没有签名配置时 **release 构建直接失败**（防止误发 debug 签名的包）；本地试跑可设
>    `SMARTSCRIPT_ALLOW_DEBUG_SIGNING=1`，但这类包不能发给用户。

## 3. 填参数（管理端「系统管理 → 参数设置」）

新增以下参数，**改完立即生效，不用重启**：

| 键名 | 值 | 说明 |
|---|---|---|
| `app.version.android.versionCode` | `2` | 必须等于 publish 脚本传的 build 号 |
| `app.version.android.versionName` | `1.0.1` | 弹窗展示用 |
| `app.version.android.url` | `http://192.168.100.3:1100/profile/app/script-app-1.0.1-2.apk` | 直链 |
| `app.version.android.size` | 脚本打印的字节数 | 下载后校验完整性；留空则不校验 |
| `app.version.android.notes` | `本次更新…` | 换行会原样展示 |
| `app.version.android.minVersionCode` | `1` 或 `2` | 低于它的手机不可跳过（强制更新） |
| `app.version.android.enabled` | `true` | 填 `false` 可临时关闭全部更新提示 |

验证（不装 App 也能测）：

```bash
curl -s http://192.168.100.3:1100/api/v1/app/version
curl -sI http://192.168.100.3:1100/profile/app/script-app-1.0.1-2.apk
```

第二条要返回 `200`、`Content-Type: application/vnd.android.package-archive`，`Content-Length` 与 `size` 一致。

**MinIO 注意**：服务器若开了 `MINIO_ENABLED=true`，`/profile/**` 读取会先查 MinIO（本地文件只是缓存），必须把 APK 也同步进公开桶，否则下载 404：

```bash
mc cp uploadPath/app/script-app-1.0.1-2.apk smartscript/smartscript-profile/app/
```

## 3.5 一键发版（推荐）

在本机执行一条命令即可，**自动完成**：检测 App 代码是否有变化 → build 号 +1 → 打包 →
上传服务器 → 同步 MinIO → 更新 `sys_config`（含 Redis 缓存清理）→ 线上验证。

```bash
cd D:/build/smart-script-app
bash scripts/release_app.sh                      # 有代码变化才发版
bash scripts/release_app.sh --notes "修复登录问题"  # 附带更新说明
bash scripts/release_app.sh --force              # 忽略「无变化」，强制发一版
bash scripts/release_app.sh --dry-run            # 只看流程，不打包不上传
```

- 版本名默认 `1.0.<build号>`（如 `1.0.5`），可用 `VERSION_NAME=1.1.0 bash scripts/release_app.sh` 覆盖。
- 「代码变化」只看 `lib/ android/ assets/ pubspec.yaml pubspec.lock`；改文档、脚本不会触发发版。
- build 号记录在 `.release-state`（已忽略提交）；首次运行自动以线上 `versionCode` 为基线。
- 需要本机有 `mysql` 客户端、`flutter`、可免密登录服务器的 SSH 密钥；
  后端 `.env.local` 或 `ENV_FILE` 指向的文件要含 `DB_URL/DB_USERNAME/DB_PASSWORD`。
- 服务器地址、目录、容器名都可用环境变量覆盖（见脚本头部）。

旧的手工流程保留在下面，脚本出问题时可以对照排查。

## 3.5 日常发版（后续每次更新都按这个走）

前提：服务器上已部署过带版本接口的后端（一次性），之后发版**不需要动后端**。

```bash
# 1) 本机打包并复制到 uploadPath/app（build 号必须递增：2 → 3 → 4 …）
cd D:/build/smart-script-app
bash scripts/publish_apk.sh 1.0.2 3

# 2) 传 APK（替换成实际文件名）
scp -i ~/.ssh/id_ed25519 build/app/outputs/flutter-apk/app-release.apk <SERVER_HOST>:/tmp/
ssh -i ~/.ssh/id_ed25519 <SERVER_HOST> "sudo cp /tmp/app-release.apk /home/ma_jiajia/uploadPath/app/script-app-1.0.2-3.apk && sudo chown ma_jiajia:ma_jiajia /home/ma_jiajia/uploadPath/app/script-app-1.0.2-3.apk"

# 3) 同步到 MinIO（必须用容器 root 凭据，且 alias 与 cp 在同一个容器内）
#    见下方脚本模板
```

MinIO 同步脚本模板（在服务器上执行）：

```bash
RU=$(sudo docker inspect smart-script-minio --format '{{range .Config.Env}}{{println .}}{{end}}' | sed -n 's/^MINIO_ROOT_USER=//p')
RP=$(sudo docker inspect smart-script-minio --format '{{range .Config.Env}}{{println .}}{{end}}' | sed -n 's/^MINIO_ROOT_PASSWORD=//p')
sudo docker run --rm --network host --entrypoint /bin/sh -v /home/ma_jiajia/uploadPath/app:/apk:ro minio/mc:latest -c "mc alias set adm http://127.0.0.1:9000 '$RU' '$RP' >/dev/null && mc cp /apk/script-app-1.0.2-3.apk adm/smartscript-profile/app/"
```

```bash
# 4) 管理端「参数设置」改三个键（其余保持不变）
#    versionCode = 3、versionName = 1.0.2、url = .../profile/app/script-app-1.0.2-3.apk
#    size 一并改成脚本打印的字节数；notes 改成这次更新说明

# 5) 验证
curl -s http://192.168.100.3:1100/api/v1/app/version
curl -s -m 60 -o /dev/null -w '%{http_code} %{size_download}\n' http://192.168.100.3:1100/profile/app/script-app-1.0.2-3.apk
```

**注意 `sys_config` 有 Redis 缓存**：通过管理端页面改会自动刷新；如果像我们一样直接改数据库，
必须删掉 `sys_config:app.version.*` 这几个键，否则接口仍返回旧值：

```bash
sudo docker exec redis-container redis-cli -a '<redis密码>' --no-auth-warning \
  --scan --pattern 'sys_config:app.version*' | xargs -r -I{} \
  sudo docker exec -i redis-container redis-cli -a '<redis密码>' --no-auth-warning DEL {}
```

**用户侧体验**：已装 App 的用户每天第一次打开（或当天第一次从后台切回）会看到「发现新版本」弹窗；
点「立即更新」在应用内下载并拉起系统安装确认。首次更新需要用户允许一次「安装未知应用」。
自动弹窗一天只弹一次，下拉通知栏、回桌面再回来不会重复弹出；想看更新随时可点「我的 → 检查更新」。
想把某次更新设为强制，把 `minVersionCode` 调到比旧包 build 号大即可（弹窗无「稍后」，且每天都提醒）。

## 4. 用一台手机走一遍真机验证

1. 装 `script-app-1.0.1-2.apk`，首次启动 → 应弹出「发现新版本 1.0.2」（先把参数 `versionCode` 改成 `3` 造一个假的新版本）。
2. 点「立即更新」→ 弹窗内进度条走完 → 出现系统安装确认框 → 安装成功。
3. 首次会先跳到「允许安装未知应用」设置页：打开开关，返回后点「立即安装」即可。
4. 点「稍后」→ 当天不再弹；下拉通知栏再回来、回桌面再回来、杀掉重进都不会再弹（一天一次）。
5. 「我的 → 检查更新」→ 无新版时提示「当前已是最新版本」；有新版时随时可以手动触发弹窗。

## 5. 已知边界

- **普通 App 无法静默安装**：最后一步的系统安装确认框必须用户点，这是 Android 限制，不是实现问题。
- **iOS 不支持**：iOS 只能走 App Store / TestFlight。
- **已装的旧包不会自动更新**：旧包没有更新逻辑，只有从 `1.0.0+1` 之后用新签名装的包才会收到提示。
- **`applicationId` 仍是 `com.example.script_app`**：一旦对外长期分发就不要再改，改了等于换一个 App。
- **备份**：keystore 与密码已备份到仓库外 `C:/Users/cimu/smartscript-signing/`（不在 `D:/build` 的 git 范围里），
  请再复制一份到 U 盘或密码管理器；丢了就无法给已装用户升级。
- **下载自检**：App 下载后会校验文件大小（填了 `size` 时）和 APK 文件头（`PK\x03\x04`），
  网关返回 200+HTML 错误页这类情况会提示重试，不会把坏包交给安装器。
